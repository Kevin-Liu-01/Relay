# Full task comparison — preregistration

## Authorized scope

- User approved **18 tasks × five models × 20 trials = 1,800 fresh episodes**, with a **$300 total estimated-spend ceiling**. This replaces the proposed 24-cell continuation; that continuation was never launched.
- Exact Router routes: `gpt-6.1-sol`, `claude-sonnet-5-5`, `gemini-3.8-flash`, `deepseek-v4.1-flash`, `glm-5p3-flash`. Catalog-discovered availability and base rates are frozen in the JSON plan and rechecked before each block. Availability is not evidence of successful inference.
- All four October 2 model-comparison attempts remain separate pilot evidence. Their accepted estimates and outstanding reservations count toward the $300 ceiling. No prior trial is substituted for a new trial.

## Design and evaluation

- Unit: one fresh model/task/fixture-seed episode. Each model receives all 18 tasks at each seed 1042–1061: **20 attempts per task/model, 360 per model**.
- Complete five-model task/seed blocks; reproducible shuffled model order. Task order is shuffled within each seed round. One worker, no overlapping workspaces, fresh browser context, private database and conversation per episode.
- First five blocks are fixed before collection: topic, thread, editing, incident triage and decision record at seed 1042. Inspect all 25 trajectories before bulk collection. This is a transport/accounting/isolation gate, not selection for a high pass rate. These 25 remain in the final matrix only if the source and settings stay unchanged.
- Accessibility browser control, no guide, recent-four observation/action history. Same prompts and frozen strict state graders for every model. No task answers in policy input, no LLM judge, no relaxed checks and no retry.
- 40 action attempts, 4,096 maximum output tokens, 250,000 conservative input units, 180-second episode deadline, 90-second request deadline bounded by remaining episode time. Sampling/reasoning use provider defaults; exact returned backend identifiers are recorded.
- Twenty seeds are repeated public template instances, **not 20 independent semantic tasks or a held-out split**. No significance, population ranking or training-performance claim. Report per-task results first, with macro averages and full denominators; do not pool these with differently configured pilots.

## Failure and resource policy

- Ordinary incorrect/step-limited trials remain evaluated failures. Request/episode timeouts, validated output-limit receipts and allowlisted transport connection failures end that episode and permit only the next planned cell after cleanup. They remain blocked/truncated, even if diagnostic checks pass.
- Validated output-limit usage replaces its reservation at frozen catalog rates. Partial output is never executed. Missing timeout/connection receipts retain their full reservation and unknown usage. No inference retry, model substitution or resetting the ledger.
- Authentication/access errors, invalid/missing receipts outside those exceptions, harness/cleanup errors, source drift, mismatched initial state and integrity failures stop collection. Hosted/console defaults do not inherit campaign continuation overrides.
- The global ledger includes prior recorded allowances plus all new blocks, including unresolved reservations. Each five-episode block receives at most $5 and no more than the global remainder; this is a sub-limit, not an additional allowance. A shared cap cannot be multiplied by launching another worker: an atomic lock refuses concurrent ownership.
- Finite ceilings: 72,000 requests, 48 hours elapsed, 20 GB compressed evidence and 10 GB minimum free storage. Zero GPU allocations. Reaching a ceiling leaves untouched trials unattempted. Catalog estimates are not provider invoices; provider-side key caps are the external billing control.
- Checkpoint at each request/episode and archive at each completed block. Resumption is permitted only between fully verified blocks with identical plan/source/launcher hashes. An interrupted block is never automatically rerun. A stale worker lock requires inspection, not blind removal.

## Evidence and presentation

- Preserve exact requests, receipts, observations, rejected actions, initial/final state, event chains, timestamps and original PNGs. Every block gets a local integrity audit and a byte-hashed archive.
- Large originals remain under the private runtime directory until separately packaged/published; do not bloat Git with gigabytes or imply unpublished archives are downloadable. Public summary/CSV show every planned row, returned routes, action attempts, outcome checks, time, usage and cost uncertainty.
- Results table: task × model, passed/attempted alongside planned 20, incomplete/blocked/not-run counts, median wall time and reported-usage estimate plus unknown reservations. Sort on raw values with unknowns last. State collection status and update time.
- Local integrity is not independent attestation. Wall time includes observer overhead; it is not time-to-success or hosted performance.
