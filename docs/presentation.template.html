{{ICON_STATE}}Final state → grader{{ICON_EVIDENCE}}Saved steps → trace and replay
  • Each run starts with a separate database and browser session containing known workspace data.
  • The model receives an observation and returns one action at a time.
  • The harness repeats this loop until the model finishes or a limit stops the run.
  • Playwright controls the browser. Separate data does not protect the host from malicious code.

  • The interface determines what the model observes and which actions it can request.
  • The actor API uses the same application rules but does not operate the browser.
  • All four paths change workspace data that the same grader can check.
  • Page JSON describes page controls, not the underlying database. Actor API access exposes broader structured data.
  • The harness uses a shared JSON action protocol, not each provider's native computer-use protocol.

The grader checks the final workspace state

  • Workspace state is the stored data: messages, threads, topics, and saved items.
  • The grader is code that compares this data with the task requirements.
  • A model's claim that it finished does not affect the result.
