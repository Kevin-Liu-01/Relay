The harness runs and records the test

  • The harness is the code that controls each test run.
  • It shows the workspace to the model and asks for one action.
  • It checks the action, executes it, and records what changed.
  • It repeats these steps until the model finishes or reaches a limit.
  • It checks the final workspace against the task requirements.
  • React builds the UI. SQLite stores workspace data. Playwright controls the browser.
  • Related projects and references. I reviewed their code but did not run a comparison.

Define the task and check the result

  • The suite has six simple tasks and 12 tasks that require several changes.
  • Example: find an approval, update the channel description, pin the message, save the reply, and acknowledge it.
  • The checks verify the text, author, destination, and required changes.
  • A run fails if it leaves a duplicate message or changes unrelated data.

Unclear tasks make failures hard to interpret

  • Thread repair passed in {{THREAD_REPAIR_RESULT}} runs. It requires finding a fact, editing a reply, and confirming the change.
  • Design handoff passed in {{DESIGN_RESULT}} runs. Six completed runs copied “DESIGN” instead of the required name.
  • The task did not clearly tell the model to replace “DESIGN” with a name.
  • Release sync also passed in {{RELEASE_RESULT}} runs. Its instructions give an unclear location for a source message.
  • Keep these recorded results. Fix the instructions before running a new version of the test.
  • Recorded actions and failure analysis. These two tasks do not provide a clear measure of model ability.
