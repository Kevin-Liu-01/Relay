Implementation scope and prior work

  • React UI, deterministic transition engine, SQLite persistence and Playwright runner.
  • Static Slack mockups supply appearance, but not reset, reward or durable outcomes.
  • Cua Slack, env0 and Agent-Diff already address related environments; this is not a novelty claim.
  • Original focused implementation keeps task contracts and failure traces easy to inspect.
  • MIT for original code; third-party asset restrictions remain separate.
  • Source review, not comparative execution: prior-work survey and pinned references.

Tasks require correct state, not a “done” response

  • Six control tasks; 12 deeper workflows with 3–6 coordinated mutations.
  • Decision record: retrieve final approval, update description, pin the root, save the reply and acknowledge in-thread.
  • Check content, identity, author, destination, uniqueness and all unchanged workspace state.
  • Wrong thread, replacement instead of edit, stale fact or collateral change fails.

What the trajectories explain

  • Thread reply: GPT-6 Luna passed through accessibility, page JSON and API; GPT-4o mini failed those matched cells.
  • Decision record: Luna pinned and saved correctly in the UI, but copied the placeholder “DESIGN” instead of the approved fact. API execution passed.
  • Pixel pilot: 20 malformed multi-action responses were rejected; no state mutation occurred.
  • Stop condition: Luna hit the 1,024-output-token limit. The incomplete response executed no action; remaining cells were not launched.
  • The runner retained the incomplete response's reservation conservatively. This was not HTTP 403 or proof of missing provider access.

  • Proposed architecture, not a measured deployment at scale.

Demonstration and discussion

  • Open the workspace: search, reply in a thread, and edit your own message.
  • Open Replays: compare the successful thread reply and the incomplete decision record.
  • Inspect the exact request, action, state change and terminal checks; replay requires no model calls.
  • Discuss: required Slack fidelity, observation contract, security boundary and cost/throughput target.
  • Next gates: successful pixel policies, task-template holdouts, trainer integration and concurrent-worker measurements.
  • Reset/step/reward are implemented; no RL training or BrowserGym/OpenEnv compatibility is claimed.
