The harness connects action to evidence

  • Observe the workspace. Ask for one action. Validate it before execution.
  • Execute with Playwright or the actor API. Record the request, response and state change.
  • Repeat within time, action and spend limits. Grade the final state and export the trace.
  • React renders the workflows. A shared transition engine writes private SQLite state.
  • MIT for original code; third-party asset restrictions remain separate.
  • Cua Slack, env0 and Agent-Diff address related environments. This is not a novelty claim.
  • Source review, not comparative execution: prior-work survey and pinned references.

Separate control service
  • A valid click is not task success. Check intended changes and the state that must stay unchanged.
  • Task wording is part of the test. Version ambiguous instructions before collecting new results.
  • Missing receipts, blocked runs and wrong answers mean different things. Preserve all three.
  • Scale with bounded workers and external evidence storage. Measure full worker memory, p95 latency and cleanup first; this diagram is a proposal.

Demo, then questions

  • Open the workspace: search, reply in a thread, and edit your own message.
  • Open trial review: choose a recorded model/task, play a success, and inspect an incomplete or blocked attempt.
  • Inspect the exact request, action, state change and terminal checks; replay requires no model calls.
  • Which Slack workflows and visual details matter for the target agent?
  • What should reward penalize beyond final state? What isolation, throughput and cost target do we need?
  • Reset/step/reward are implemented; no RL training or BrowserGym/OpenEnv compatibility is claimed.
  • Next gates: successful pixel policies, held-out task templates, trainer integration and sustained worker tests.
